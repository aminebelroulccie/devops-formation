# React example — built with Node, served by nginx

_English version · la version française est dans [`README.md`](README.md)_

**What this example shows**: for a front-end, the build tooling (Node, npm, `node_modules`,
often > 500 MB) has no place in production. We build in `node:22-alpine`, then copy only the
`dist/` folder into an **unprivileged nginx**. The final image is ≈ 50 MB and contains no
server-side JavaScript at all.

```bash
docker build -t formini-hello-react .
docker run --rm -p 8080:8080 formini-hello-react
open http://localhost:8080/       # the page shows "Bonjour Formini" and the /health status
curl -s localhost:8080/health     # ok
docker images formini-hello-react
```

> First build: `npm ci` requires a `package-lock.json`. If it is missing, run `npm install`
> once on your workstation (it generates the file) and commit it. That file is what makes the
> build reproducible.

## Things to notice

- `COPY package.json package-lock.json*` then `npm ci` **before** `COPY . .`: package
  downloads stay cached as long as the lock file does not change.
- `nginxinc/nginx-unprivileged` runs as user 101 and listens on **8080**, not 80: a non-root
  process cannot bind a port below 1024 without a special capability.
- `nginx.conf`: `try_files … /index.html` fallback for client-side routing, immutable cache on
  `/assets/` (Vite fingerprints the file names), `/health` answered without touching the disk.
- The `HEALTHCHECK` uses `wget`, which Alpine ships (`curl` is not included).

# Terraform on AWS — three nodes ready for Kubespray

_English version · la version française est dans [`README.md`](README.md)_

Three Ubuntu 24.04 machines in **the same subnet**, connected to the Internet through an
**Internet Gateway** (the VPC's router), each with an **Elastic IP** (AWS's floating IP: fixed,
detachable, reassignable), and a Kubespray inventory generated automatically.

```
                 Internet
                    │
          ┌─────────┴─────────┐
          │ Internet Gateway  │   the subnet's 0.0.0.0/0 route; DNAT of the Elastic IPs
          └─────────┬─────────┘
   VPC 10.42.0.0/16 · public subnet 10.42.1.0/24 (a single, shared one)
      │              │              │
   node1 .11      node2 .12      node3 .13      ← fixed private IPs
   EIP 1          EIP 2          EIP 3          ← Elastic IP, one per node
   control plane  worker         worker
   etcd           etcd           etcd
```

| File | Content |
|------|---------|
| `versions.tf` | providers `aws ~> 5.0` and `local`, default tags (`Project`, `Owner`, `ManagedBy`) |
| `variables.tf` | `owner`, `node_count` (3), `instance_type` (`t3.medium`), `admin_cidr`, CIDRs… |
| `main.tf` | VPC, subnet, Internet Gateway, route table, security group, key, 3 instances, 3 Elastic IPs, inventory |
| `cloud-init.yaml` | node preparation: hostname, swap off, Kubernetes kernel modules and sysctl |
| `inventory.tpl` | Kubespray inventory template (`hosts.yaml`) filled in by Terraform |
| `outputs.tf` | Elastic IPs, private IPs, `ssh` commands, inventory path, API URL |

What `terraform apply` creates:

1. **Network**: a `10.42.0.0/16` VPC, a `10.42.1.0/24` subnet, the Internet Gateway and the
   default route to it.
2. **Firewall** (security group): all traffic **between nodes** (etcd, kubelet, CNI, IP-in-IP),
   and from `admin_cidr` only: SSH 22, Kubernetes API 6443, NodePorts 30000-32767.
3. **SSH key**: your public key from Day 1.
4. **Three nodes** `node1`, `node2`, `node3` (`t3.medium`, 30 GB gp3) with predictable private IPs
   `.11`, `.12`, `.13`, prepared by cloud-init, `source_dest_check` disabled for Calico.
5. **Three Elastic IPs**, one per node, associated with the instances.
6. **`inventory/hosts.yaml`**: the Kubespray inventory, written by Terraform from the real IPs.

## 1. Create the infrastructure

```bash
cd ateliers/jour4-iac-kubernetes/exemples/terraform-kubespray
cp terraform.tfvars.example terraform.tfvars && nano terraform.tfvars   # owner, admin_cidr
aws sts get-caller-identity                                              # same credentials as on Day 4
terraform init
terraform plan
terraform apply            # 2 to 3 minutes
terraform output           # Elastic IPs, ssh commands, inventory path
```

Test: `ssh ubuntu@<EIP of node1>` then, from node1, `ping 10.42.1.12` (nodes see each other on
their private IPs) and `curl -I https://deb.debian.org` (Internet egress through the gateway).

## 2. Install Kubernetes with Kubespray

From your workstation or the Formini VM (Python 3.10+, SSH access to the three Elastic IPs):

```bash
git clone --branch v2.26.0 --depth 1 https://github.com/kubernetes-sigs/kubespray.git
cd kubespray
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

# the inventory generated by Terraform + Kubespray's default configuration
cp -r inventory/sample inventory/formini
cp ../terraform-kubespray/inventory/hosts.yaml inventory/formini/hosts.yaml
ansible -i inventory/formini/hosts.yaml all -m ping           # the three nodes answer "pong"

# 15 to 25 minutes
ansible-playbook -i inventory/formini/hosts.yaml cluster.yml -b -v

# fetch the kubeconfig from the control plane and point it at the Elastic IP
ssh ubuntu@<EIP node1> 'sudo cat /etc/kubernetes/admin.conf' > ~/.kube/formini.conf
sed -i 's#https://10.42.1.11:6443#https://<EIP node1>:6443#' ~/.kube/formini.conf
export KUBECONFIG=~/.kube/formini.conf
kubectl get nodes -o wide
```

Useful Kubespray settings before running `cluster.yml` (files in `inventory/formini/group_vars/`):

- `k8s_cluster/k8s-cluster.yml`: `kube_network_plugin: calico` (default), `cluster_name: formini.local`,
  `supplementary_addresses_in_ssl_keys: [<EIP node1>]` so the API certificate accepts the Elastic
  IP (otherwise `kubectl` needs `--insecure-skip-tls-verify`).
- `k8s_cluster/addons.yml`: `metrics_server_enabled: true`, `ingress_nginx_enabled: true`.

Then the Day 4 Go + React stack deploys unchanged:
`kubectl apply -k ../exemples/go-react/k8s/`; the NodePort 30081 Service is reachable on
`http://<EIP of any node>:30081` (30081 is inside the range opened by the firewall).

To share this cluster between students, one namespace and one kubeconfig each:
[`../namespaces-etudiants/`](../namespaces-etudiants/README.en.md).

## 3. Destroy

```bash
terraform destroy
```

Three `t3.medium` plus three Elastic IPs cost money by the hour (and an unassociated Elastic IP
is billed even with the instance stopped): destroy at the end of the session, and the trainer
checks with `setup/aws/cleanup-check.sh`.

## What to observe

- **The Elastic IP is a resource of its own** (`aws_eip`), bound to the instance by
  `aws_eip_association`: an instance can be replaced and given back the same public address.
  `associate_public_ip_address = false` avoids a pointless second, ephemeral public IP.
- **`cidrhost(var.subnet_cidr, 11 + count.index)`**: computed addresses, nothing hard-coded, and
  the same code for 3 or 5 nodes (`node_count`).
- **`templatefile` + `local_file`**: Terraform writes the Ansible inventory; the infrastructure and
  its inventory never drift apart.
- **Internal traffic by group reference** (`referenced_security_group_id`), not by address range:
  a newly added node is allowed automatically.
- **`source_dest_check = false`**: without it, AWS drops the pod traffic that Calico routes
  (source address different from the instance's).
